# 存档里通用组件的编码（从 50 份官方教学存档统计，2026-10-10）

来源：`scripts/dev/comp_table.mjs` 跑全部 `knowledge/samples/gil/*.gil`，`scripts/dev/comp_dump.mjs <种类码>` 把某一种组件的所有写法展开，`scripts/dev/prefab_diff.mjs` 逐字段比对（金币 vs 路牌、宝箱 vs 路牌）。

**已做成工具并在游戏里验证（2026-10-10）**：碰撞触发器（5）、选项卡（17）、自定义变量（1）由 `scene_add_components` 写入，节点图挂载由 `scene_add_graph` 的 `attachToPrefab` 写入；实测结果在 `docs/PLATFORM_RULES.zh-CN.md` 的“组件加事件”一节。其余种类码只看过官方存档，还没写过。

## 记录在哪、长什么样

- 元件模板在存档第 4 段，每个条目一个元件；`f7` 是基础组件列表（变换、模型等，每条 `f1` 是种类，内容在 `f(10+种类)`），**`f8` 是通用组件列表**，同样的写法：`f1` = 种类码，`f2` = 1，内容在 `f(10+种类码)`。一个元件可以有多条 `f8`。
- 摆在场景里的实体（第 5 段）只带 `f6` 覆盖项，组件配置本体在元件模板上。它的 `f6#2.f12.f2.f1` 在带触发器的元件上是一个大数（如 100010090），路牌上为空——**已确认：这是物件的预设状态编号**（`f2` 是初始值），和有没有触发器无关，只和用的是哪个资产有关。见 `preset-status.zh-CN.md`。
- 节点图挂载在**基础组件** `f7#3`（摆放实体是 `f6#3`）：`f13` 里每张图一条 `f1{f1{f1=1, f2=图ID, f501=20000}}`，多张图就是多条。玩家模板（基础模板号 1000000，每个玩家位各有一个实体）和角色模板（1000001）也是这样存的。已验证。
- 摆在场景里的实体自己带一份和元件相同的记录（实体的 `f7` 对应元件的 `f8`），所以改元件要连同它已摆放的实体一起改，工具就是这么做的。

## 碰撞触发器（种类码 5，内容 `f15`）的样子

金币元件（教程“碰撞与交互”功能示例-1，生效目标仅角色、缩放 2）：

```
f8 { f1=5  f2=1
  f15 { f1 {               // 一个触发器
      f1=1  f2=1           // 序号 / 初始生效？
      f3 = bytes 01 02     // 生效目标清单？（教程里选了“仅角色”）
      f4 { f11 { f1{} f2{2,2,2} f3{} }   // 区域：位置、缩放、旋转
           f502 "区域1"  f503=1 }
      f502 "触发器 序号:1"  f503 = bytes 00 } } }
```

## 选项卡（种类码 17，内容 `f27`）的样子

宝箱元件（功能示例-2，选项文案“开启宝箱”、区域缩放 3）：

```
f8 { f1=17  f2=1
  f27 { f1 { f11 { f1{} f2{3,3,3} f3{} }  f502 "区域1"  f503=1 }   // 触发选项区域
        f2 { f1=1  f2 "开启宝箱"  f3=1 f4=1 f5=1  f6{}            // 选项：序号、文案、图标/排序/初始生效？
             f503 "开启宝箱  序号: 1"  f504=13 } } }
```

`f502/f503/f504` 这类 500 号字段是编辑器显示用的标签，运行时多半不读。

## 各字段的含义（比对 23 种触发器写法、40 种选项卡写法得出）

- 触发器：`f1` 序号；`f2=1` 初始生效（没有这个字段就是初始不生效）；`f503` 是生效目标的编号（0 角色，另两个按官方列举顺序取 1 物件、2 造物），`f3` 是没选的那些；`f4` 可以有多条，每条一个区域。
- 区域：盒形 `f11{f1 中心偏移, f2 三轴大小, f3 旋转}`；球形 `f1=1, f12{f1 中心偏移, f2 半径}`。
- 选项：`f1` 序号、`f2` 文案、`f3=1` 初始生效、`f4` 图标编号（样例里见过 1、2、3、10、12、15、20）、`f6{f1=1, f2=过滤器图ID}` 是本地过滤器。
- 自定义变量：`f3` 类型（1 实体、3 整数、4 布尔、5 浮点、6 字符串、8 整数列表、13 实体列表、17 阵营、27 结构体），默认值在 `f4.f(10+类型).f1`，为零或空时省略。
- 基础组件 `f7#5` 是原生碰撞：实心物件 `f15{f1=1,f2=1}`，官方金币这类可穿过的是空的。

## 运动器的字段（2026-10-10 深夜补，已做进 `scene_add_components`）

- 基础运动器（4）：新版编辑器每个运动器存成 `f3{f1 名字, f2=1 初始生效, f501 序号, f511{f11{f1 用时, f2 速度向量, f501 位移向量}, f502{f2=1000, f502{}}}, f512{…}, f513{…}}`，整条记录最后有 `f505=1`。速度等于位移除以用时。`f512`、`f513` 两块在所有直线运动的样例里完全相同，照抄。旧版存成 `f1{…}`（没有 511～513），官方较早的样例里还能看到。路径运动是 `f511{f1=2, f13{}, f502{f2=1001 或 1002, f501 路点…}}`，旋转是路点里的旋转向量，都还没做。
- 跟随运动器（9）：`f2` 挂点名（样例里是 default 或 GI_RootNode），`f6` 1100 完全跟随、1101 只跟随位置，`f7{f11{}}` 是吸附，`f7{f1=2, f13{…}}` 是按速度追。
- **教训**：这两块里有好几个值是浮点数 1.0 而不是整数 1。`comp_dump.mjs` 的输出里浮点写作 `float 1`，整理时不要把 `float` 去掉，否则照着写出来的记录差几个字节，只有逐字节比对才看得出来。

## 内容字段号的规则（2026-10-10 深夜更正）

前面写的“内容在 `f(10+种类码)`”只对种类码 20 及以下成立。从 21 起是 `f(11+种类码)`：19 在 f29，20 在 f30，21 在 f32，27 在 f38，32 在 f43（对照表里的“内容字段”一列本来就是这样，只是我总结规则时没注意到中间跳了一格）。代码里是 `contentField(kind)`。

## 小地图标识（32）和铭牌（27）

- 小地图标识已做进 `scene_add_components` 的 `minimapMarker`，写出的记录和官方“目标点”逐字节相同，待实机验证。字段：`f501{f501 标记序号, f502=1, f504 名字, f505=1 显示高低差, f509{f501 图标编号, f503=101}, f516 描述, f517 "标记"}`。图标编号样例里用的是 12046；用造物头像时多一个 `f508=4`，图标处填的是图集路径。
- 铭牌只看懂了大概，没做工具：`f38{f501{f503 挂点名, f505 可见半径, f506 偏移, f507/f508 导航指示器的半径, f510=1 启用导航指示器, f511 指示器的内容条目…, f512 铭牌的内容条目…}}`。内容条目分文本框和图标两种（`f501=1` 是图标，图标编号见过 11001、11044、11068），每个条目里两种类型的默认块都带着。新版记录还引用一个配置编号（`f604{f1=1, f2=1140850694}`），这个编号在别处怎么登记没查清，所以没敢照写。

## 路径运动器（2026-10-10 傍晚补，已做进 `scene_add_components` 的 `motions`）

官方样例里基础运动器实际只有三种用法：一次性直线（门升起、石板上升）、开局就来回走的平台、原地一直转的图标。后两种都是路径运动器，写在同一个 `f511` 块里，开头不同：

- 直线：`f511{f11{f1 用时, f2 速度向量, f501 位移向量}, f502{f2=1000, f502{}}}`
- 路径：`f511{f1=2, f13{}, f502{f2=循环类型, f501 路点…, f502{}}}`，路点是 `{f2 相对位置, f3 绝对旋转, f4 到达时长（秒，从上一个点算）, f5=900, f7{}, f8{}}`

循环类型：1000 单程，1001 往返（到头就反向走回来，一直重复），1002 循环（到头瞬移回起点重来）。来回平台 = 一个路点 + 1001 + 初始生效；原地旋转 = 两个只有旋转的路点（180°、360°）+ 1002 + 初始生效。初始生效是运动器块里的 `f2=1`。

每个运动器块后面固定跟着 `f512`、`f513` 两块（`f513` 里也有 `f1=2 f13{}`，别把它当成“这是路径运动”的标志——我第一次统计就是这么数错的）。
