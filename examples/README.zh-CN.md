# 样例

每个样例都是只调 MCP 工具从一张空白地图搭出来、并用脚本在游戏里走过的。目录里有三样东西：

- `gen_*.py`：按图生成节点图源码（Genshin-TS），开头的注释说明玩法和每张图管什么。
- `*_test.json`：一轮的全部参数：场景、元件、组件、技能、货币等各个工具的参数，以及试玩脚本（按键、点击、截图时刻）。`about` 里写着这一轮在游戏里的结果。
- `WALKTHROUGH.md`：全过程，每一步工具调用（带参数和返回的编号）和每张图的源码，由 `scripts/dev/write_walkthrough.mjs` 从一次真实运行的记录生成，不要手改。没有文件的 AI 用 `read_knowledge {id:"example-<目录名>"}` 读它。

跑一轮：`scripts/dev/mcp_round.mjs`（环境变量 `ROUND_ARGS` 指向测试 json），细节见 `scripts/dev/README.md`。

## 做到“能给人玩”的一个

| 目录 | 玩法 | 规模 | 走通的路线 |
|---|---|---|---|
| `kingdom5` | 王国往深里做：每个动作有声音和特效、昼夜各有音乐、能买的站点上方有标记、买不了冒问号、价格是一排小金币、五夜波次递增、农夫回本、弓手的箭看得见、王冠要抢几秒（跑开能躲） | 13 张图约 1740 节点 | `kg5_test.json` 两夜短流程到胜利；`kg5_play.json` 完整一局（约九分钟）到胜利；`kg5_test_defeat.json` 被偷光后丢王冠判负 |
| `kingdom6` | 王国里的人活了：村民、农夫、工匠、飞刀手、士兵和怪全是复杂造物，自己走位、干活、打仗，战斗是平台自己的。墙有血，被怪一刀刀砍、天亮工匠一锤锤补回来；士兵持剑跃斩是攻击盒，飞刀是追踪投射物；怪手里有刀（小怪粗砍刀，大怪是拿大刀的丘丘暴徒），在墙前守着一条线砍一刀跳回去，不会穿墙；谁倒下由销毁事件报，人数跟着减。君主不挨打，没墙时被抢金币、抢王冠 | 37 张图（大多几个节点；关卡实体那张约 610） | 三条脚本都上机走通：`kg6_test.json` 两夜短流程到胜利（两夜里每秒截两张，配 `playtest_frames` 逐帧看攻击）、`kg6_test_defeat.json` 没墙被抢光判负、`kg6_play.json` 完整一局（五夜约九分钟，数值在 `kg6_rules_play.json`，先用 `balance6.py` 的粗略模型调、再上机跑过）。另有 `kg6_bench.json`：不是给人玩的，是看墙前打斗用的试验台（短流程的第一天接一夜很多怪，一分多钟） |

数值在 `kg5_rules.json`（`balance.py` 不进游戏按规则算几种打法的输赢），反馈用的特效、音效、音乐编号在 `kg5_feel.json`。好不好玩要人来玩，脚本只验证跑得通。

## 单项的验证关

| 目录 | 验证什么 |
|---|---|
| `events` | 最小的事件驱动范例：拾币加付款，四张小图。新做东西先抄它 |
| `checks` | 十五项小检查：货币、技能、信号、预设状态、运动器、跟随、出生点、预设点、计时器、能力单元、小地图、过滤器等各用一次 |
| `skills` | 带动画的技能：挥剑（手里有剑）、耙地、伸手 |
| `strike` | 技能图里打攻击盒：箱子（受击盒）和怪挨打、掉战利品、捡起 |
| `shoot` | 远程攻击：技能发射一个带投射运动器和命中检测的元件 |
| `shop` | 货币、道具、商店：在平台自带的商店界面里买和卖 |
| `drops` | 掉落物和战利品：按 F 捡起；箱子被销毁后留下掉落物 |
| `potion` | 可以使用的道具：道具节点图、背包里点“使用”，以及道具的三个事件 |
| `buttons` | 屏幕上的交互按钮：数字键触发，玩家模板上的图收事件 |
| `presets` | 机关物件的预设状态：用试玩校验筛出哪些物件有哪个状态编号 |
| `brain` | 复杂造物：一个斥候按服务器写的变量走位、干活、闲逛，一个弓手对指定目标放技能；决策图、状态图、技能图各怎么写 |
| `fitting` | 近看间：把复杂造物摆到镜头前逐个放动作，正面看它手里有什么、挂上去的武器跟不跟手，侧面量一刀往前带多远；全程连拍，`playtest_frames` 拼成逐帧图读出手时刻。技能图每跑一次打印一次，用来核对给的时刻（三连击给三个时刻就打印三次）。改 `fit_spec.py` 里的 `SHOWS` 换造物和动作 |
| `skirmish` | 复杂造物打起来，而且每种攻击都是那个动作本来的样子：农夫白天抡镐挖地夜里回家，飞刀手和士兵入夜上岗，敌人自己找上来；士兵手里的剑是挂在武器挂接点上的模型，镐和飞刀由技能在动作期间显示；近战是技能图在落刀那一刻触发的攻击盒，飞刀是追着目标飞、只碰敌人的投射物；血量、伤害数字和倒下都是平台的。王国第六版的打法从这里来 |
| `listen` | 试听：每三秒放一条音效（或音乐、带声音的特效）并录音，`scripts/dev/measure_sounds.py` 量出每条的时长、响度、明亮程度。挑音效、确认声音能播时用 |
| `clientui` | 客户端界面（游戏 7.1 的 Lua 脚本）：三个圆点跟着玩家变量走，点按钮给节点图发信号，条跟着分数变长。界面和节点图互通的最小范例 |
| `clientgame` | 整局用 Lua 写的 2D 小游戏：方向键挪篮子接金币，逐帧动画和按键都在客户端脚本里，输赢发信号给节点图结算（赢和输两条路线都走通） |
| `clientlist` | 客户端控件的其余几种：控件模板（脚本运行时照着造圆点）、网格视窗（十二个列表项）、模板引用、预设按钮、按键提示，以及不靠脚本就显示的静态图片 |
| `clientmenu` | 一个商店样子的界面：脚本变量、模板自带的脚本（每个列表项各跑一次）、子控件上的脚本、有悬停和按下样子的预设按钮、旋转缩放、一开始不激活的控件、界面动效 |
| `clientcheck` | 客户端脚本出错时是什么样：语法错在试玩开始时报出来，运行时的错带调用栈进日志；另验了隐藏的容器由节点图打开、信号带参数、传送不重置界面、`OnUpdate` 默认不跑 |
| `clientvars` | 脚本变量的二十种类型，和控件各自给公开变量的取值：同一个脚本挂在根上和一个控件上，各自把读到的值打印出来；另带分设备布局、手柄导航、文本视窗的写法 |
| `pairs` | **整局用 Lua 写的游戏**「翻牌配对」：开始界面、照模板现造的十二张牌、翻牌动画、音效、计时条、暂停、输赢结算；赢和输两条路线都按脚本打到平台的结算界面。只用工具做成，第一次试玩就通（写进去时检查器先抓到了一个名字错误） |
| `clienttext` | 屏幕上的文字（奇匠 Lv.2 才显示）：文本框的对齐、颜色、描边、背景、字号自适应，带和不带滚动条的文本视窗，脚本运行时改文字，跟着变量走的普通文本框 |
| `clientapi` | Lua 接口里容易漏的几样：图片填充做的进度条和冷却圈（要开遮罩才生效；另有一排直接写进存档的填充、羽化、反转，不用脚本）、关卡时停、音效、画布大小和设备、按路径找控件 |
| `signalparams` | 带好几个参数的信号（整数、浮点数、字符串、三维向量、布尔值、列表、实体），三条路各走一遍：节点图发给节点图、Lua 脚本发给节点图、节点图发回 Lua 脚本；两边把收到的每个值打印出来 |
| `clientsignal` | 节点图给客户端脚本发信号（`f.sendSignal('client:名字', 玩家)`，游戏 7.1 的【发送客户端脚本信号】节点），不带参数和带一个字符串各一次，脚本收到后换灯的颜色 |

## 旧的

`kingdom`（王国 v3）是有组件工具之前写的：关卡实体上一张大图每拍轮询坐标。能跑，但负载高，也不是平台本来的用法；留着是因为 `kingdom4`～`kingdom6` 的远景和村民清单还用它的文件，平台规则里引用的几个探测脚本也在里面。
